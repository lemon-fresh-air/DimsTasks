# DimsTasks

Local-first PWA таск-менеджер. Інтерфейс українською, mobile-first, без залежностей, бекенду й акаунтів. Дані живуть в IndexedDB браузера.

## Збірка
- `python scripts/build.py` → `dist/`. Працює з будь-якої директорії.
- Локально: `python -m http.server 8000 --directory dist`. Service worker і PWA перевіряй лише через localhost або HTTPS, file:// не підходить.
- Редагуй лише `src/` і `static/`. `dist/` генерується, руками не чіпай і не коміть (він у `.gitignore`).
- Порядок JS задає `scripts/build.py`: db → model → import-export → ui → app. Новий JS-файл додай у список там.
- Порядок CSS: tokens → base → app.
- Після кожної завершеної зміни запускай збірку.

## Де що
- `src/js/db.js` — IndexedDB, `DB_VERSION`, upgrade-кроки
- `src/js/model.js` — фабрики сутностей, обчислювані правила
- `src/js/import-export.js` — формат бекапу
- `src/js/ui.js`, `src/js/app.js` — відображення, події, запуск
- `src/html/app.html` — розмітка
- `src/css/` — стилі й токени
- `static/` — manifest, service-worker, іконки (копіюються в `dist/`)
- `docs/data-model.md` — модель даних і правила її розширення

## Інваріанти
- Без npm, фреймворків, CDN, бекенду, аналітики. Виняток лише за прямою згодою.
- Дані: `docs/data-model.md` читай перед будь-якою зміною схеми. Міграція ніколи не очищає й не перестворює БД.
- Нові дозволи браузера (сповіщення, геолокація, камера) не додавати без домовленості.
- Шляхи відносні, сумісні з підшляхом GitHub Pages.
- Дані користувача при тестах не чіпати: використовуй окремий профіль браузера або копію.

## Продукт
`docs/product.md` — користувач, головна дія, пріоритети першого екрана, візуальний напрям.

## Деплой
Push у `main` запускає `.github/workflows/pages.yml`: CI сам збирає `dist/` і публікує його на Pages. Push, зміни репозиторію й налаштувань Pages роби лише з прямого дозволу.
