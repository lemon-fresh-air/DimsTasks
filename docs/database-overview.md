# Як організовані дані DimsTasks

Дані користувача зберігаються **локально на пристрої** в IndexedDB браузера. GitHub містить лише код застосунку та опис структури — завдання, списки й проєкти туди автоматично не надсилаються.

## Структура бази

База `dims-tasks-db`, версія `2`, має чотири окремі сховища:

| Сховище | Що містить |
|---|---|
| `lists` | Списки завдань, включно із системним Інбоксом |
| `sections` | Секції всередині списків |
| `projects` | Проєкти, їхні цілі, терміни та статуси |
| `tasks` | Завдання та посилання на список, секцію і проєкт |

Завдання завжди належить списку. Секція і проєкт необов'язкові. Порядок завдань у списку та порядок кроків у проєкті зберігаються окремо.

## Спільні поля

Кожен запис має стабільний `id`, версію сутності, час створення та оновлення. Поле `customFields` дозволяє тимчасово додавати експериментальні атрибути.

Нові звичайні поля можна додавати без зміни версії бази. Версія IndexedDB підвищується лише тоді, коли потрібне нове сховище, індекс або міграція наявних даних.

## Сумісність і резервні копії

При переході зі старої версії наявні завдання зберігаються та автоматично отримують нові поля. JSON-резервна копія містить усі чотири сховища; старий формат копій також підтримується.

Повний технічний опис: [`data-model.md`](data-model.md).
