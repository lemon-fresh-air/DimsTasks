# Збережені кроки проєкту — специфікація

Це точка правди для майбутньої реалізації. Поточний код ще не підтримує описану поведінку. Папка «Пізніше / колись» є окремою функцією: збереження кроків працює у звичайному завданні будь-якого списку.

## Представлення даних

Кроки зберігаються структурованим полем `savedSteps` запису Task, незалежним від `description`. Це **не текстовий синтаксис і не Markdown**. Markdown в описі завдання не розбирається для пошуку кроків. Поле відсутнє у старих записах; під час читання відсутнє поле еквівалентне порожньому масиву. Нове поле не потребує нового object store чи індексу IndexedDB.

```js
savedSteps: [
  { title: "Вибрати стіл", description: "Ширина до 120 см", status: "active",
    listId: "list-id", sectionId: "section-id-or-null" }
]
```

Порядок елементів масиву є порядком кроків у проєкті; окреме поле позиції в знімку не потрібне. `title` — непорожній рядок, `description` — рядок (може бути порожнім), `status` — `active` (або `completed` у старому знімку), `listId` — непорожній рядок, `sectionId` — рядок або `null`. Збережений крок — знімок, а не чинний Task: він не має власного ID, посилання `projectId`, дат чи позицій у списку. Старі дедлайни кроків не відновлюються. Опис кроку зберігається повністю, без обрізання чи інтерпретації Markdown.

Це поле належить тільки самостійному завданню (`projectId: null`). Воно не має посилатися на чинні кроки проєкту. Видалення списку чи секції не переписує знімок: їхні ID залишаються для перевірки при відновленні. Порожній масив можна не записувати; інтерфейс трактує його як відсутність збережених кроків.

## Проєкт → завдання

У наявному діалозі перетворення є три взаємовиключні варіанти: «Зберегти кроки в завданні» (типово), «Залишити кроки окремими завданнями» і «Видалити кроки». Якщо проєкт не має кроків, нове поле порожнє, а блок у редакторі завдання не показується.

У варіанті збереження беруться лише активні невиконані кроки проєкту; виконані й архівні кроки видаляються разом із проєктом. Кроки сортуються за наявним правилом `projectPosition` із детермінованим розв'язанням рівності. З кожного беруться `title`, `description`, `status`, `listId`, `sectionId`. Створюється звичайне активне завдання в корені «Нові» зі знімком; вихідний проєкт і його кроки видаляються. Опис нового завдання — опис проєкту без доданого службового тексту. Інші два варіанти зберігають свою чинну семантику та не створюють `savedSteps`.

Створення завдання, видалення проєкту й кроків виконується однією транзакцією. Збій залишає попередній стан повністю. Поки кроки збережені, вони не існують як окремі завдання у списках, «Сьогодні» чи проєкті.

## Показ у редакторі завдання

Одразу під полем опису показується початково згорнутий блок «Збережені кроки · N» **лише якщо** `savedSteps` є непорожнім масивом. Для звичайного завдання блок і його місце в розкладці повністю відсутні. У розгорнутому стані показуються назва, повний опис, стан і список кожного кроку. Відсутній список позначається як «Нові» (місце майбутнього відновлення). Це перегляд; редагування знімка не входить у першу версію. Усі назви та описи виводяться безпечно як текст або через той самий безпечний Markdown-рендеринг, який використовує звичайний опис.

## Завдання → проєкт

Активне самостійне завдання зі збереженими кроками перетворюється на активний проєкт за чинним правилом перенесення назви, опису й дати самого завдання. Інтерфейс повідомляє кількість кроків, які будуть відновлені. Для кожного елемента знімка створюється нове завдання з новим ID, збереженими назвою, описом і станом. Старі знімки з виконаним станом відновлюються з `completedAt` на час відновлення; активний крок — із `completedAt: null`. `projectPosition` призначається послідовно відповідно до порядку масиву.

Перед записом для **кожного** кроку перевіряється поточна наявність списку. Якщо список зник, використовується «Нові» та `sectionId: null`. Якщо список існує, секція відновлюється лише коли вона досі існує й належить цьому списку; інакше `sectionId: null`. Позиція у вибраній області списку призначається за чинними правилами додавання завдань без витіснення або непередбачуваного перемішування старих завдань. Дедлайни кроків і старе членство у плані «Сьогодні» не відновлюються. Вихідне завдання видаляється після створення проєкту й усіх кроків у **тій самій транзакції**. Якщо знімок некоректний, перетворення не починається і вихідне завдання залишається.

Самостійне завдання без `savedSteps` перетворюється за чинною поведінкою: проєкт без кроків. Не копіювати `savedSteps` до `customFields` проєкту.

## Сумісність і перевірка

- Старі локальні завдання та старі резервні копії без поля читаються як `savedSteps: []`.
- Експорт має переносити масив без втрат; імпорт перевіряє його форму й типи. Внутрішні `listId` і `sectionId` знімка можуть посилатися на вже видалені записи — це допустимо. Під час злиття різні версії одного Task, як і зараз, вибираються за `updatedAt`; масив не зливається поелементно.
- Покрити тестами обидва напрями, порядок, описи, активний стан і сумісність зі старим виконаним знімком, зниклий список, зниклу або перенесену секцію, старий запис без поля, некоректний знімок і атомарність при збої.
- Оскільки змінюються дані завдання та імпорт/експорт, виконати перевірку рівня 3 за `AGENTS.md`, окрім відповідних модульних тестів.

Перед реалізацією звірити цю специфікацію з `docs/data-model.md` і оновити обидва документи, якщо узгоджене рішення зміниться.
