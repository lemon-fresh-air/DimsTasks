# DimsTasks: ручне сценарне тестування UI та UX

Цей посібник допоможе пройти застосунок як звичайний користувач і знайти місця, де щось ламається, незрозуміло працює або просто дратує. Не потрібно відкривати код, консоль чи базу даних.

**UI** — чи добре все видно та чи зручно натискати. **UX** — чи зрозуміло, що робити, що сталося після дії та як повернутися або виправити помилку.

Не намагайся довести, що застосунок працює. Спробуй зробити в ньому звичайні справи й помічай, де він тобі заважає.

## 1. Як організувати прогін

### Скільки часу потрібно

- Короткий прогін основних дій: 20–30 хвилин після підготовки.
- Повний прогін: приблизно 60–90 хвилин. Можна розділити на кілька підходів.
- Повтор після виправлень: проблемний сценарій і одна сусідня дія, зазвичай 5–15 хвилин.

Спочатку пройди сценарії 1–10 на телефоні. Потім — масові дії, жести та видалення. Наприкінці перевір тему, ПК і повторне відкриття. Встановлення та офлайн перевіряються окремо.

### Де тестувати

Для основного прогону використовуй той телефон і браузер, де плануєш користуватися DimsTasks. Якщо зазвичай запускаєш встановлений застосунок, головний прогін роби саме там.

Локальний `dist/index.html` підходить для перевірки екранів, карток і дій. Встановлення, оновлення та офлайн перевіряй на опублікованій HTTPS-версії.

Дані локальні: інший браузер, профіль, пристрій або адреса можуть мати окремий набір завдань. Відсутність даних на іншому пристрої сама по собі не означає втрату — синхронізації між пристроями немає.

### Перед початком

1. Запиши дату, пристрій і де відкрито застосунок: адреса сайту, локальний файл або встановлена PWA.
2. Якщо знаєш версію чи коміт — додай, але спеціально шукати не потрібно.
3. Для видалення та експериментів використовуй тільки тестові записи. Познач їх словом «Тест».
4. Не очищай дані браузера, щоб «почати з нуля»: це може стерти звичайні завдання.
5. Якщо тестуєш серед своїх записів, працюй лише зі створеними нижче тестовими списками й проєктами.
6. У НаГ перевір перемикач повернення прострочених завдань до «Нові». Для початку вимкни його та запам’ятай попереднє значення. Окремий сценарій перевірить цю функцію пізніше.

У поточному інтерфейсі не слід розраховувати на кнопку експорту або імпорту: наявність внутрішньої підтримки резервних копій ще не означає, що така дія доступна в меню.

### Як проходити кожен сценарій

1. Прочитай мету й підготуй потрібні записи.
2. Виконай кроки у звичайному темпі.
3. Порівняй побачене з очікуванням.
4. Якщо щось дивне — коротко запиши. Не потрібно відразу шукати причину.
5. Якщо безпечно, повтори один раз, щоб зрозуміти, чи проблема повторюється.
6. Продовжуй наступний сценарій. Якщо проблема блокує його — познач «не перевірено».

Не став галочку лише тому, що зміг якось обійти проблему. Якщо довелося вгадувати або пробувати три різні кнопки, це вже корисна UX-знахідка.

## 2. Назви екранів

| Скорочення | Що це | Як знайти |
| --- | --- | --- |
| ГМ | Головне меню, усі списки | «Огляд» у нижній навігації |
| КС | Конкретний користувацький список | Вибрати список у ГМ |
| ВП | Усі проєкти | «Проєкти» у нижній навігації |
| КП | Конкретний проєкт | Натиснути проєкт на ВП |
| НаКП | Налаштування проєкту | Кнопка редагування на КП |
| НаГ | Глобальні налаштування | Шестерня в ГМ |
| Деталі завдання | Відкрита картка / редактор завдання | Натиснути завдання у списку або на КП |

«Нові» та «Сьогодні» — системні екрани. «Сьогодні» показує завдання за датою, а не є окремим місцем їх зберігання.

## 3. Підготуй тестовий набір

Підготовка теж є тестуванням. Якщо вже тут незрозуміло, як створити список або додати крок проєкту, запиши це.

### Списки

Через ГМ створи:

1. **Тест — Дім**.
2. **Тест — Робота та особисті справи з довгою назвою**.
3. **Тест — Порожній** — поки нічого сюди не додавай.

Довга назва потрібна, щоб перевірити перенесення, обрізання й доступність кнопок. Якщо поле обмежує довжину, використай назву, яку воно дозволяє зберегти.

### Звичайні завдання

Створи їх через інтерфейс. «Сьогодні», «вчора» та «завтра» означають дні відносно фактичної дати прогону.

| Назва | Де створити | Дата й час | Для чого |
| --- | --- | --- | --- |
| Тест — Купити хліб | Дім | Без дати | Коротка картка |
| Тест — Розібрати всі коробки на балконі та вирішити, які речі залишити, віддати або викинути | Дім | Без дати | Довга назва |
| Тест — Замовити лампочку | Дім | Вчора, без часу | Прострочений дедлайн |
| Тест — Полити квіти | Дім | Сьогодні, без часу | Екран «Сьогодні» |
| Тест — Забрати посилку | Дім | Завтра, без часу | Майбутня дата |
| Тест — Дзвінок | Довгий список | Сьогодні, час пізніше поточного | Час у картці |
| Тест — Підготувати нотатки | Довгий список | Через тиждень | Календар і опис |
| Тест — Ідея на потім | Нові | Без дати | Вхідне завдання |
| Тест — Можна видалити А | Дім | Без дати | Свайп і скасування |
| Тест — Можна видалити Б | Дім | Без дати | Масове видалення |

Якщо сьогодні вже майже північ, для майбутнього часу використовуй завтра. Перевірку «Сьогодні» тоді виконай окремо із завданням без часу.

Для «Підготувати нотатки» встав опис:

> Зібрати питання перед зустріччю.
>
> Перевірити попередні домовленості, виписати незрозумілі моменти та підготувати короткий перелік наступних кроків.
>
> Окремо подумати, що можна завершити цього тижня, а що потребує більше часу. Не забути уточнити строки й відповідальних.

### Проєкти

Створи **«Тест — Оновити робоче місце»**:

- Мета: «Зручний стіл, освітлення та порядок у кабелях».
- Опис: кілька речень або опис із попереднього прикладу.
- Термін: через тиждень.
- Зворотний відлік: увімкнений.
- Кроки в такому порядку: «Виміряти стіл», «Вибрати лампу», «Замовити органайзер», «Розкласти кабелі».

Через деталі кроків признач їм список «Тест — Дім». Першому кроку постав сьогодні, другому — завтра, іншим прибери дату.

Створи **«Тест — Порожній проєкт»** без завдань і терміну. Його використаєш для порожнього стану та безпечного видалення.

### Важливе правило проєктів

Звичайний список показує лише поточний незавершений крок проєкту. Усі кроки дивись на КП. Після виконання поточного кроку наступний має з’явитися у своєму списку.

Тому чотири кроки на КП та один у КС — очікувана поведінка. Але якщо інтерфейс цього не пояснює і здається, що три завдання загубилися, це варто записати як проблему зрозумілості.

## 4. Сценарії основного прогону

### Сценарій 1. Знайти потрібний екран і повернутися

**Мета:** зрозуміти, чи легко орієнтуватися без підказок.

1. Відкрий «Нові».
2. Перейди у «Сьогодні».
3. Відкрий ВП.
4. Відкрий ГМ через «Огляд» і знайди «Тест — Дім».
5. Зайди у КС, відкрий завдання та повернися стрілкою застосунку.
6. Повернися в ГМ, зайди у НаГ та повернися назад.
7. Повтори переходи швидше, наче шукаєш конкретне завдання.

**Очікування:** заголовок відповідає екрану, немає двох екранів поверх один одного, активний розділ зрозумілий, кнопки не зникають. Після повернення ти можеш продовжити роботу без повторного пошуку.

**На що звернути увагу:** чи зрозуміло, що «Огляд» відкриває списки; чи плутається заголовок списку із назвою завдання; чи стрілка назад веде туди, куди очікуєш.

Розділ «Скоро» зараз позначений як той, що розробляється. Відсутність готового екрана не записуй як нову поломку. Якщо його стан незрозумілий користувачу — це UX-зауваження.

### Сценарій 2. Створити завдання у конкретному списку

1. Зайди у «Тест — Дім» і натисни плюс.
2. Введи «Тест — Нова справа».
3. Перевір атрибут «Список»: чи вибрано «Тест — Дім».
4. Прибери дату, якщо вона підставилася автоматично.
5. Збережи завдання штатною дією. На телефоні стрілка редактора має зберігати й повертати до списку.
6. Знайди нове завдання й відкрий його повторно.
7. Повернися та створи ще два короткі завдання поспіль.

**Очікування:** кожне з’являється один раз у правильному списку; назва збережена; дата після очищення відсутня; лічильник оновлюється відповідно до видимих завдань.

**Перевір зручність:** чи одразу зрозуміло, як зберегти; чи клавіатура не закриває вихід; чи для наступного завдання не доводиться проходити зайві екрани.

### Сценарій 3. Порожня назва та відмова від створення

1. Натисни плюс, нічого не введи й повернися.
2. Перевір, що порожня картка не з’явилася.
3. Відкрий створення ще раз, введи тільки пробіли й спробуй зберегти.
4. Якщо редактор залишився відкритим, введи нормальну назву й збережи.
5. Відкрий нове завдання, введи назву, потім зітри її повністю та повернися.

**Очікування:** порожні завдання не створюються, немає завислого редактора чи дублювання. Якщо потрібне виправлення, зрозуміло, що саме зробити.

**Увага:** стрілка в деталях завдання є збереженням і виходом. Не вважай її автоматично кнопкою «Скасувати». Якщо це неочевидно — запиши.

### Сценарій 4. Редагування назви та довгого опису

1. Відкрий «Тест — Підготувати нотатки».
2. Зміни назву, додавши «до зустрічі».
3. Додай до опису ще два абзаци та порожній рядок.
4. Постав курсор на початок, у середину та в кінець опису.
5. Прокрути редактор із відкритою клавіатурою.
6. Збережи й відкрий завдання ще раз.
7. Прибери опис повністю, збережи та перевір картку.

**Очікування:** текст не губиться, переноситься й редагується без стрибків курсора; до кінця опису можна дістатися; очищений опис не залишає старого прев’ю. Довга назва не витісняє кнопки за межі екрана.

**Перевір зручність:** чи видно, який текст редагуєш; чи не потрібно боротися з двома прокрутками; чи легко вийти після появи клавіатури.

### Сценарій 5. Прочитати картки з різним наповненням

1. Відкрий «Тест — Дім».
2. Порівняй коротке завдання, довгу назву, завдання з описом і поточний крок проєкту.
3. Подивись на картку з двома бейджами: проєкт і список.
4. Натисни інформаційний бейдж проєкту у списку.
5. Повернися та повільно прокрути всі картки.

**Очікування:** назва має повну доступну ширину текстової частини; бейджі розташовані нижче й за потреби переносяться; картка збільшує висоту; текст і кнопка виконання не перекриваються. Список показаний і для завдання без проєкту. Порожній бейдж проєкту не з’являється.

Бейдж у списку не є окремим переходом на КП: натискання в цій області відкриває деталі завдання разом із рештою картки. Перехід до проєкту має бути в атрибутах усередині деталей.

**Перевір зручність:** чи можеш швидко прочитати назву та відрізнити список від проєкту; чи бейджі не забирають забагато уваги; чи обрізана довга назва бейджа все ще впізнавана.

### Сценарій 6. Призначити, змінити й прибрати дату

Це головний регресійний сценарій для виправленої помилки з датою створення.

1. Відкрий «Тест — Купити хліб», у якого немає дати.
2. Відкрий вибір дати, вибери «Сьогодні» та збережи дату.
3. Збережи завдання й перевір картку.
4. Повтори із «Завтра».
5. Вибери конкретний день через тиждень у календарі.
6. Вибери вчорашній день і перевір позначення прострочення.
7. Знову відкрий дату, вибери «Без дати», збережи дату та завдання.
8. Перевір картку, відкрий деталі, повернися та перезавантаж сторінку.
9. Повтори очищення дати для поточного кроку проєкту. Перевір його і в КС, і на КП.

**Очікування:** картка показує саме обрану дату; після очищення рядок дати повністю зникає і після перезавантаження не повертається. Дата створення не підставляється замість дедлайну. В деталях кнопка «Без дати» допустима й потрібна для нового вибору.

Прострочений активний дедлайн має відповідне червоне позначення. Однакові дедлайни в однаковому стані повинні виглядати послідовно на різних екранах.

### Сценарій 7. Час і скасування вибору дати

1. Відкрий завдання з датою завтра.
2. Відкрий вибір часу й установи, наприклад, 14:30.
3. Підтвердь час, дату й завдання. Перевір дату з часом на картці.
4. Знову відкрий час, зміни його на 16:45, але натисни «Скасувати» у діалозі часу.
5. Перевір, що попередній час не замінився скасованим значенням.
6. Зміни день у календарі, але закрий вибір дати хрестиком без «Зберегти». Відкрий його ще раз.
7. Прибери тільки час через «Без часу», збережи й перевір картку.
8. Постав час знову, потім прибери всю дату та збережи.
9. Признач нову дату. Переконайся, що старий час не повернувся самовільно.

**Очікування:** скасований вибір не змінює збережене значення; очищення часу залишає день; очищення дня прибирає і час. У картці без дати немає окремого часу.

**Перевір зручність:** чи легко вибрати хвилини; чи зрозуміла різниця між «Готово» в часі та «Зберегти» в даті; чи видно поточний вибір.

### Сценарій 8. Екран «Сьогодні»

1. Перевір, що «Полити квіти» має сьогоднішню дату без часу.
2. Відкрий «Сьогодні» й знайди його.
3. Переконайся, що завдання без дати, на завтра та на вчора тут не показані.
4. Відкрий завдання звідси й перенеси дату на завтра. Повернися.
5. Перевір, що воно зникло зі «Сьогодні», але лишилося у своєму КС.
6. Створи завдання зі «Сьогодні», вибравши «Тест — Дім» у полі списку.
7. Створи наступне: перевір, чи запам’ятався останній успішно використаний список.
8. Зміни список у новій порожній формі та вийди без створення. Перевір, що це не змінило типовий список для наступного створення.

**Очікування:** «Сьогодні» є добіркою за датою; бейдж списку показує справжній список. Перенесення дати прибирає завдання з добірки без видалення самого запису.

За поточним правилом завдання з уже минулим сьогоднішнім часом вважається простроченим і не показується у «Сьогодні». За бажанням перевір це окремим тестовим завданням. Якщо така поведінка незручна, запиши її як побажання змінити правило.

### Сценарій 9. Перемістити завдання між списками

1. Відкрий звичайне завдання з «Тест — Дім».
2. В атрибутах зміни список на довгий робочий список.
3. Збережи та перевір обидва списки.
4. Відкрий переміщене завдання й перевір назву, опис та дату.
5. Перемісти його в «Нові», потім назад у «Тест — Дім».
6. Повтори перенесення для поточного кроку проєкту.

**Очікування:** завдання існує в одному списку, бейдж відповідає новому списку, інші атрибути зберігаються. Крок проєкту лишається на КП і не втрачає зв’язок із проєктом після зміни списку.

**Перевір зручність:** чи легко знайти потрібний список; чи зрозумілий вибраний варіант; чи довга назва не робить меню непридатним.

### Сценарій 10. Перейти з деталей завдання на КП

1. У КС відкрий поточний крок «Тест — Оновити робоче місце».
2. Знайди атрибути «Список» і «Проєкт».
3. Натисни «Проєкт».
4. Перевір назву відкритого КП.
5. На КП відкрий інший крок, переглянь його атрибути та повернися.
6. Відкрий звичайне завдання без проєкту: порожнього переходу на проєкт бути не повинно.

**Очікування:** відкривається саме пов’язаний проєкт, попередній редактор не залишається поверх нього. Кнопки й прокрутка працюють після повернення.

**Окрема перевірка збереження:** у тестовому кроці зміни назву й одразу натисни атрибут проєкту. Повернися до кроку та перевір назву. Якщо зміна загубилася без попередження — запиши проблему. Не припускай, що будь-який вихід автоматично зберігає текст.

### Сценарій 11. Проєкт: мета, опис і термін

1. Відкрий КП «Тест — Оновити робоче місце».
2. Перейди у НаКП.
3. Зміни назву, мету й опис. Збережи.
4. Перевір оновлені дані на КП, ВП і бейджі поточного кроку в КС.
5. Розгорни та згорни довгий опис на КП.
6. Зміни термін, увімкни та вимкни зворотний відлік.
7. Прибери термін і перевір, що старий термін та відлік не лишилися на КП.
8. У НаКП зміни назву, але вийди кнопкою скасування. Перевір результат.
9. Спробуй зберегти порожню назву. Потім віднови нормальну та збережи.

**Очікування:** збережені зміни послідовно відображені скрізь; порожня назва не приймається; скасування не зберігає чернетку; відлік має сенс лише з установленим терміном.

**Перевір зручність:** чи видно різницю між КП і НаКП; чи зрозуміло, де редагувати та як зберегти; чи повідомлення про стан збереження помітне.

### Сценарій 12. Послідовні кроки проєкту

1. Відкрий КП із чотирма кроками та перевір їх порядок.
2. Подивись на прогрес проєкту.
3. Відкрий КС, до якого належить перший активний крок.
4. Виконай цей крок кнопкою з галочкою.
5. Перевір, що поточним став наступний крок. Якщо він належить іншому списку, шукай його там.
6. Повернися на КП: перевір стан виконаного кроку й прогрес.
7. Додай новий крок і перевір, що він з’явився один раз.
8. Розгорни список завдань проєкту, прокрути до останнього кроку та згорни назад.
9. Перезавантаж застосунок і перевір порядок та прогрес.

**Очікування:** поточний крок визначається порядком незавершених кроків. Виконання одного кроку не завершує весь проєкт автоматично: завершення проєкту — окрема дія.

**Перевір зручність:** чи очевидно, який крок виконувати далі; чи легко відрізнити виконане; чи зрозумілі числа прогресу; чи розгортання не губить навігацію.

### Сценарій 13. Масовий вибір і зміна атрибутів

1. У КС затисни тестове завдання, щоб увійти в режим вибору.
2. Вибери ще два завдання натисканнями.
3. Перевір кількість вибраних і виділення карток.
4. Зніми вибір з одного завдання.
5. Зміни дату для решти на завтра.
6. Перевір, що невибране завдання зберегло свою дату.
7. Вибери два завдання повторно та перенеси їх в інший тестовий список.
8. Вийди з вибору й натисни картку: має відкритися звичайний редактор.
9. Повтори зміну дати для двох кроків на КП.
10. Для двох вибраних завдань прибери дату та перевір картки після збереження.

**Очікування:** змінюються лише вибрані записи; кількість відповідає виділенню; вихід із режиму зрозумілий; картки після завершення знову працюють звично.

**Перевір зручність:** чи можна зрозуміти режим без читання лічильника; чи довге натискання не спрацьовує під час звичайної прокрутки; чи піктограми масових дій зрозумілі.

### Сценарій 14. Порядок і жести

1. У КС підготуй три звичайні активні завдання з різними назвами.
2. Перетягни нижнє вище інших, використовуючи наявний жест утримання та перенесення.
3. Перевір порядок після відпускання й після перезавантаження.
4. Вибери два завдання та перевір перенесення групи, якщо цей режим доступний.
5. На КП увійди в режим вибору й перестав кроки проєкту.
6. Перевір, чи змінився поточний крок відповідно до нового порядку.
7. У ГМ перестав два тестові списки й перевір порядок після повторного відкриття.
8. Зроби короткий горизонтальний рух по тестовій картці, потім відпусти; окремо зроби звичайну вертикальну прокрутку.

**Очікування:** видно, що саме рухається і куди стане; записи не дублюються та не зникають; вертикальна прокрутка не видаляє завдання; незавершений жест не залишає картку в зламаному положенні.

Не оцінюй ручний порядок через «Сьогодні»: цей екран має власні правила сортування за датою та часом. Для перестановки використовуй КС і КП.

Якщо не можеш зрозуміти, як почати перетягування, не витрачай десять хвилин на вгадування. Запиши «не знайшов, як переставити» й продовжуй.

### Сценарій 15. Виконання, видалення та «Відмінити»

Виконуй лише на тестових записах, які можна втратити.

1. Виконай звичайне завдання в КС і перевір, що активний список оновився.
2. Якщо з’явилася дія «Відмінити», натисни її до зникнення повідомлення та перевір повернення запису.
3. Видали «Можна видалити А» свайпом.
4. Якщо є «Відмінити», поверни завдання й перевір його назву, дату та список.
5. Повтори видалення й дочекайся завершення повідомлення.
6. Перезавантаж сторінку: остаточно видалений запис не має повертатися.
7. Вибери два інші одноразові завдання й видали масово. Якщо є підтвердження, спочатку скасуй його та перевір записи, потім повтори з підтвердженням.

**Очікування:** дія стосується саме вибраного запису або групи; «Відмінити», якщо пропонується, реально повертає дані; лічильники оновлюються. Якщо можливості повернення немає, це має бути достатньо зрозуміло до ризикованої дії.

**Перевір зручність:** чи встигаєш помітити повідомлення та натиснути «Відмінити»; чи його не перекриває нижня навігація; чи можна випадково видалити замість прокрутки.

### Сценарій 16. Перейменування та видалення списку

1. Відкрий «Тест — Порожній», перейди до редагування списку.
2. Зміни назву та скасуй: перевір стару назву.
3. Зміни назву ще раз і збережи: перевір ГМ та заголовок КС.
4. Спробуй зберегти порожню назву, потім поверни нормальну.
5. Додай у цей список одне завдання «Тест — Пережити видалення списку».
6. Почни видалення списку, скасуй і перевір, що список та завдання лишилися.
7. Повтори видалення й підтвердь.
8. Перевір, що список зник, а завдання перейшло в «Нові».
9. Відкрий завдання та перевір його бейдж і атрибут списку.

**Очікування:** видалення користувацького списку не видаляє його завдання; вони переходять у «Нові». Інтерфейс має допомогти зрозуміти цей наслідок до підтвердження.

### Сценарій 17. Завершення та видалення проєкту

1. Відкрий тестовий проєкт і натисни завершення.
2. Спочатку скасуй підтвердження: проєкт має лишитися активним.
3. Повтори й підтвердь. Знайди його серед завершених на ВП.
4. Відкрий завершений проєкт і перевір доступ до його даних.
5. Поверни його в активні та перевір ВП.
6. Для видалення використай «Тест — Порожній проєкт». Додай до нього один одноразовий крок і запам’ятай його список.
7. Почни видалення проєкту, спочатку скасуй, потім повтори з підтвердженням.
8. Знайди крок у його списку та відкрий деталі.

**Очікування:** завершення і видалення відрізняються. Після видалення проєкту його завдання залишаються у своїх списках, але більше не мають проєктного бейджа чи переходу на видалений КП.

Не припускай, що завершення проєкту автоматично виконує всі його кроки. Перевір, чи результат відповідає тексту дії та твоєму очікуванню; суперечність запиши.

### Сценарій 18. Автоматичне повернення прострочених у «Нові»

Цей перемикач стосується всіх відповідних завдань у поточній базі. Якщо тут є важливі особисті записи, пропусти сценарій або виконай його в окремому тестовому профілі.

1. При вимкненому перемикачі створи в тестовому КС два активні завдання з датою вчора.
2. Перезавантаж: вони мають лишитися у КС.
3. Відкрий НаГ і ввімкни повернення прострочених до «Нові».
4. Перевір, що обидва завдання з’явилися в «Нові» й зникли зі старого КС.
5. Перевір, що дедлайни збереглися та лишилися простроченими.
6. Перезавантаж двічі: записів не повинно стати більше.
7. Вимкни перемикач. Уже перенесені завдання не повинні автоматично повертатися назад.
8. Наприкінці поверни початкове значення налаштування.

**Очікування:** перенесення одноразове, дата не стирається, дублікати не з’являються. Текст налаштування має достатньо пояснювати наслідки.

## 5. Перевірки вигляду та зручності

### Сценарій 19. Порожні екрани

1. Відкрий порожній користувацький список.
2. Відкрий порожній проєкт до його видалення або створи ще один тимчасовий.
3. Якщо можливо без зміни особистих даних, перевір порожнє «Сьогодні».

**Перевір:** чи видно, що список справді порожній, а не завантажується; чи зрозуміло, як додати перший запис; чи плюс доступний; чи текст не обіцяє неіснуючу кнопку. Після додавання запису повідомлення про порожній стан має зникнути.

### Сценарій 20. Телефон, клавіатура та довгі екрани

1. Пройди КС, деталі завдання, календар, вибір часу, КП та НаКП.
2. На кожному екрані прокрути донизу.
3. Відкрий клавіатуру в назві та довгому описі.
4. Спробуй дістатися до збереження й повернення без закриття застосунку.
5. Поверни телефон у горизонтальне положення та назад.
6. Якщо зручно, тимчасово збільш системний розмір тексту на один крок, повтори ключові екрани й поверни налаштування.

**Перевір:** немає горизонтальної прокрутки всього екрана; остання картка доступна; плаваючий плюс не перекриває потрібну кнопку; нижня навігація не накриває текст; форма не втрачає введене після повороту; довгі назви не стискаються до кількох літер у рядку.

**Практичне питання:** чи можеш натискати звичним хватом і пальцем, не прицілюючись? Якщо постійно промахуєшся — записуй, навіть коли кнопка технічно працює.

### Сценарій 21. Світла й темна тема

1. У НаГ увімкни темну тему.
2. Переглянь КС із довгими картками, «Сьогодні», ВП, КП, деталі, календар і вибір списку.
3. Увімкни масовий вибір та перевір вибрані картки.
4. Перевір прострочену дату, підписи, обидва бейджі та неактивні кнопки.
5. Перезавантаж застосунок і перевір збереження теми.
6. Поверни світлу тему й швидко переглянь ті самі елементи.

**Очікування:** текст читається в обох темах, вибране помітне, спливаючі меню мають правильний фон, немає світлих плям чи невидимих іконок. Червона дата читається без надмірної яскравості.

Не орієнтуйся лише на колір: назва дати й контекст повинні допомагати зрозуміти стан.

### Сценарій 22. ПК і клавіатура

На ПК можуть бути окремі дані. Достатньо створити один тестовий список, проєкт і кілька карток.

1. Відкрий широке вікно, потім поступово звузь його до телефонної ширини.
2. Перевір назви, бейджі, редактор і кнопки збереження.
3. Натискай Tab та Shift+Tab: пройди кнопки й поля.
4. Перевір видимість фокусу й активацію кнопок Enter або пробілом.
5. У назві тестового завдання перевір Enter; у багаторядковому тексті — звичайне введення кількох рядків.
6. Перевір Escape окремо у відкритому меню та редакторі тестового завдання. Запиши, що фактично сталося.
7. Збільш масштаб браузера до 200%, перевір основні дії, потім поверни його.

**Очікування:** основні дії доступні без миші; видно поточний фокус; приховані екрани не перехоплюють його; при звуженні елементи перебудовуються; при збільшенні масштабу важливі кнопки лишаються доступними.

Escape у редакторі не обов’язково означає скасування: перевір узгодженість із фактичним способом збереження та запиши, якщо результат несподіваний.

## 6. Збереження та встановлена PWA

### Сценарій 23. Перезавантаження і повторний запуск

Перед перевіркою запам’ятай або сфотографуй стан одного списку та одного проєкту.

1. Зміни назву завдання, опис і дату, збережи.
2. Перемісти інше завдання між списками.
3. Виконай один крок проєкту.
4. Зміни порядок кількох звичайних завдань.
5. Перезавантаж сторінку та перевір кожну зміну.
6. Закрий вкладку або встановлений застосунок, відкрий знову в тому самому браузері / профілі та за тією самою адресою.
7. Перевір дані ще раз.

**Очікування:** збережені зміни лишаються; старі дати, видалені записи та попередні назви не повертаються; немає дублікатів. Початковий відкритий екран може відрізнятися — це окрема UX-оцінка, а не доказ втрати даних.

Якщо щось зникло, не очищай сховище й не перевстановлюй застосунок. Запиши останні дії та адресу, де перевіряв.

### Сценарій 24. Встановлення й офлайн — тільки опублікована версія

1. Відкрий HTTPS-версію з інтернетом і дочекайся повного відкриття.
2. Якщо браузер пропонує встановлення, встанови застосунок звичайним способом.
3. Відкрий його з іконки та перевір, чи є очікувані дані.
4. Вимкни інтернет на пристрої.
5. Повторно відкрий застосунок.
6. Створи одноразове завдання, зміни його назву й дату, збережи.
7. Закрий і відкрий застосунок без інтернету, перевір зміни.
8. Увімкни інтернет та переконайся, що нічого не продублювалося.

**Очікування:** після підготовленого онлайн-відкриття застосунок доступний офлайн, а локальні дії зберігаються. Якщо браузер не пропонує встановлення, запиши браузер і доступні варіанти меню; це потребує окремої перевірки, а не обов’язково означає збій самого застосунку.

Цей сценарій не перевіряється відкриттям локального HTML-файлу.

### Сценарій 25. Оновлення після нової публікації

Проходь тільки коли справді опубліковано нову версію з помітною зміною.

1. До оновлення створи тестове завдання з упізнаваною назвою.
2. Відкрий застосунок після публікації з інтернетом.
3. Перевір, чи з’явилася очікувана зміна інтерфейсу.
4. Якщо ні — закрий застосунок повністю, відкрий знову та повтори перевірку.
5. Перевір збереження тестового завдання, списків і проєктів.

**Очікування:** нова версія стає доступною без втрати локальних даних. Якщо видно старий інтерфейс, запиши це окремо як проблему отримання оновлення. Не очищай дані браузера заради нової версії.

## 7. Вільний прогін: 10 хвилин реального користування

Після сценаріїв зроби невелику справжню сесію планування:

1. Запиши п’ять справ, які прийшли в голову.
2. Розклади їх по списках.
3. Обери дві на сьогодні.
4. Створи маленький проєкт із трьох кроків.
5. Зміни плани: перенеси дату, перемісти завдання, виконай один крок.
6. Спробуй знайти конкретне завдання, не пам’ятаючи точно, де воно лежить.

Тут не звіряй кожну кнопку. Помічай, де губиш думку, довго шукаєш дію, робиш зайві переходи або боїшся втратити введене. Такі спостереження часто корисніші за косметичні дефекти.

## 8. Коли можна закінчувати

Прогін достатній, якщо ти перевірив створення, редагування, дату, переміщення, виконання, проєкт, повернення назад і збереження після перезапуску. Решту можна перенести на наступний підхід.

Після виправлення проблеми повтори її кроки на тій версії, де є виправлення. Потім перевір одну сусідню дію: наприклад, після виправлення очищення дати — знову встанови дату; після виправлення переходу на КП — відкрий звичайне завдання без проєкту.

На завершення видали лише свої одноразові тестові записи, якщо вони заважають, та поверни змінені налаштування. Можна залишити тестовий набір для наступного прогону.

## 9. Як записувати проблеми — максимально просто

Один пункт — одна проблема. Достатньо **де → що зробив → що не так / як хотів**. Скрин або відео додавай, коли словами незручно. Причину шукати не потрібно.

```md
Телефон / браузер: ...
Тестував: сайт / локальний файл / встановлений застосунок
Дата: ...

- КС «Дім» → прибрав дату й повернувся → на картці лишилося «Вчора». Має зникнути.
- КП → відкрив довгий опис → не можу дістатися до останнього рядка. Скрин 1.
- Завдання → натиснув проєкт → загубилася змінена назва. ВАЖЛИВО.
- ГМ → шукав додавання списку → довго не міг зрозуміти, яку кнопку натиснути.
```

Якщо сильно заважає або губить дані — допиши **ВАЖЛИВО**. Якщо трапилося лише раз — **було один раз**. Якщо хочеш іншу поведінку — **хочу так: …**. Цього достатньо, щоб потім розібрати й повиправляти.
