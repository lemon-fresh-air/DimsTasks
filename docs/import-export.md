# Імпорт і експорт даних DimsTasks

DimsTasks зберігає дані локально в IndexedDB браузера (`dims-tasks-db`). Акаунта чи сервера для синхронізації немає: перенесення між пристроями відбувається через JSON-файл резервної копії. Керування розміщене в глобальних налаштуваннях застосунку (НаГ).

## Експорт

Застосунок читає одним узгодженим знімком п’ять сховищ: `lists`, `sections`, `projects`, `tasks`, `settings`. Перед створенням файлу він доповнює записи актуальними полями, нормалізує денні плани й перевіряє цілісність даних. JSON має оболонку `format: "local-first-pwa-backup"`, `appId: "dims-tasks"`, `formatVersion: 26`, довідковий `databaseVersion`, час `exportedAt` і об’єкт `data` з масивами цих п’яти сховищ.

Типове ім’я файлу: `Dimstasks-1---18-Nov-2026.json` (префікс можна змінити; дата береться з локального часу пристрою). Номер наступної копії зберігається в `settings`. Якщо вибрана папка бекапів і браузер підтримує File System Access API, файл записується туди без перезапису однойменного файлу; інакше запускається звичайне завантаження браузером. Максимальний розмір копії — 50 МБ.

## Імпорт

Користувач вибирає JSON-файл або відкриває папку бекапів. Для папки за замовчуванням береться найновіша придатна копія за `exportedAt` (за відсутності дати — за часом зміни файлу); автоматичний вибір можна вимкнути й вибрати файл вручну. Шлях до папки не входить у копію: браузер зберігає доступ лише локально в окремій IndexedDB `dims-tasks-local-files` і за потреби знову запитує дозвіл.

До запису застосунок відхиляє файли понад 50 МБ, невалідний JSON, чужий `appId`/`format`, непідтримувану версію та пошкоджені записи або зв’язки. Підтримуються формати 1–26; старі записи приводяться до поточної структури. Після перевірки показуються дата копії, версія формату й кількість записів. Далі користувач обирає:

- **Замінити всі дані** — відтворити вміст копії замість локальних записів.
- **Злити дані** — додати відсутні ID; при збігу ID взяти запис із пізнішим `updatedAt`, а при рівності залишити локальний. Видалення не передаються, бо журналу видалень немає. Результат повторно перевіряється на цілісність.

Обидва режими записують усі п’ять сховищ однією транзакцією IndexedDB: помилка не залишає часткового імпорту. Після імпорту протягом трьох секунд доступне скасування, яке повертає попередній локальний знімок. Нумерація бекапів при відновленні не відмотується назад: враховуються локальний лічильник, лічильник у JSON та номер з імені файлу.
